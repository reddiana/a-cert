# 평가자1
Hazelcast 유료화에 따른 비용과 기술 종속 문제를 해결하기 위해 Java 기반 분산 코디네이션 엔진을 직접 설계·구현하고, 락과 큐, 리더 선출, 장애 복구를 체계적으로 시험한 점이 강점입니다. 주요 목표를 PoC에서 확인했고, 기존 BatchService와의 호환성을 고려한 현장 재사용 자산으로도 의미가 있습니다. 다만 시험 환경은 가상 네트워크와 임시 저장소 중심이라 실제 운영 환경의 네트워크 지연, 영속 저장, 노드 장애 상황까지 충분히 보여주지는 못했습니다. 운영에 가까운 다중 노드와 영속 볼륨 환경에서 반복 검증하고, 기존 서비스 전환 파일럿을 통해 안정성과 운영 부담, 비용 효과를 확인한 뒤 확산하는 것이 좋겠습니다. Raft와 분산 락 등 검증된 패턴을 직접 구현하고 조합한 과제인 만큼, 기존 Hazelcast 구성과 비교해 어떤 차별적 이점과 기여가 있는지 구체적으로 정리하면 좋겠습니다.

# 평가자2
본 과제는 Hazelcast 유료화에 대응해 BatchService의 분산 락·큐·리더 선출을 JDK 표준 기반 자체 Raft 엔진으로 대체 하기 위한 설계 내용을 기술하고 있습니다. 요구사항 분석 부터 9개 품질 시나리오와 7개 설계 결정을 도출하고 구현 코드와 Chaos Mesh 기반 K8s 장애 주입 검증까지 일관되게 연결해 문서 완성도가 매우 높으며, 검증 중 발견한 결함을 회귀 테스트로 포함한 부분도 돋보입니다. 다만 대안 비교가 대부분 DB 장애 내구성에 대한 기준으로 결정 되는점, 싱글노드 minikube 결과는 네트워크 지연에 민감한 락 성능을 대표하지 않는 부분이 보이며, 향후 현작 과제 적용 시 자원 소모 측정과 운영 규격 다중 노드, VM 환경 재검증에 대한 보강이 이루어 지면 좋을것 같습니다. 

# 평가자3
DB 의존성과 배치 고가용성 문제를 해결하기 위해 분산합의와 복구 메커니즘을 깊이 있게 설계·구현한 고난도 설계를 진행하였습니다.
메타 DB 장애에도 배치 실행을 유지하기 위한 분산합의·상태 관리·복구 문제를 다뤄 난이도가 높습니다. Raft, WAL, Multi-FSM, fencing과 복구 흐름을 연결한 상세 설계가 강점입니다.
요구사항과 시험의 연결 및 측정 기준이 명확하지만, 분산 엔진의 현장 신뢰성에는 장시간 운영과 복합 장애 검증이 추가로 필요해 보입니다.
