### 1.3 이슈 및 요구사항 분석 (Issue and Requirement Analysis)

프로젝트 아키텍처 수립의 기반이 되는 주요 기술적/비즈니스적 이슈와 이를 해결하기 위한 요구사항을 분석함.

#### 1. 이슈 목록 (Issue List)
| Issue ID | 이슈 내용                                                        | 영향도 |          비고          |
| :------: | :----------------------------------------------------------- | :-: | :------------------: |
|  IS-01   | Hazelcast 라이선스 정책 유료화 변경으로 인한 상용 비용 발생 및 컴플라이언스 리스크          |  상  |  오픈소스 종속성 탈피의 핵심 원인  |
|  IS-02   | 스케줄러 자체의 가벼운 기능에 비해 Hazelcast(IMDG)의 자원(메모리/CPU) 점유율이 과도함    |  중  | 소규모(3~5개) 노드 환경에 부적합 |
|  IS-03   | 네트워크 단절 또는 노드 다운 시 클러스터 자가 치유(Self-Healing) 지연으로 인한 배치 누락 위험 |  상  |    고가용성(HA) 확보 필수    |
|  IS-04   | 자체 구현한 신규 분산 엔진 적용 초기 단계의 잠재 결함(데드락 등)으로 인한 대형 사이트 운영 장애 리스크 |  상  |  안정성 검증 및 비상 대책 필수   |

#### 2. 요구사항 목록 (Requirement List)
| Req ID | 요구사항 정의                                                                            | 관련 Issue ID  | 우선순위 |
| :----: | ---------------------------------------------------------------------------------- | :----------: | :--: |
| REQ-01 | 외부 라이브러리(Hazelcast 등)를 완전히 제거하고 Java Standard API(JDK)로만 분산 기능 구현                  | IS-01, IS-02 |  필수  |
| REQ-02 | 다중 노드 환경에서 배치 Job의 중복 실행을 완벽히 방지하는 분산 락(Distributed Lock) 제공                       |    IS-03     |  필수  |
| REQ-03 | 작업 유실을 방지하고 FIFO(First-In-First-Out) 및 동시 폴링을 지원하는 분산 큐(Distributed Queue) 제공      |    IS-03     |  필수  |
| REQ-04 | 노드 장애 시 3~5초 이내에 상태를 감지하고 새로운 리더를 선출하는 자가 치유(Self-Healing) 제공                      |    IS-03     |  필수  |
| REQ-05 | 운영 안정성 위협 시 설정(Configuration) 변경만으로 기존 Hazelcast 엔진으로 복귀할 수 있는 롤백 방안 및 하위 호환 구조 제공 |    IS-04     |  필수  |
